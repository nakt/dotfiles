## TL;DR

今回の棚卸しでは「rules からは手順の粒度を落とし目的だけを書く。スキル側の具体手順が常に優先される」という原則を採った。代替案として rules の各項目を「制約（破ると実害。スキルも例外なし）」と「既定（スキルが理由を書けば上書きしてよい）」の 2 層に分ける案があったが、今回は目的形への書き換えで足りると判断して見送った。

## 背景 / 問い

Claude Code 設定群の棚卸しで rules の記述粒度を検討した際に出た代替案。今回採用した「目的だけを書く」方式との比較で、上書き可否を文面から判別できる利点がある 2 層方式をどう位置づけるかが未決着。

## 調査結果

- 採用した方式: rules は目的（なぜそのルールがあるか）のみを書き、手順の具体はスキル側に委ね、スキル側の具体手順が常に rules の記述に優先する
- 代替案（2 層方式）: rules の各項目を以下の 2 種に分類して明示する
  - 制約: 破ると実害があり、スキル側でも例外を許さない
  - 既定: スキルが理由を明記すれば上書きしてよい
- 2 層方式の利点: 上書き可否が rules の文面自体から判別でき、`claude-config-audit` のような監査でも「このスキルはこの rules を正当に上書きしているか」を機械的に判定しやすくなる
- 今回見送った理由: 目的形への書き換えだけで当面の重複・矛盾は解消できると判断したため

## 結論 / プラン

- [ ] 2 層方式を rules 全体に適用するか、目的形との部分併用（一部の rules だけ 2 層化する）が可能かを検討する
- [ ] 採用する場合は「実害」と「既定」の分類基準を先に固める

## 未解決の論点 / リスク

- 2 層方式は rules 全体の書き直しコストが発生する。目的形との併用（一部の rules だけ 2 層化する）が可能かは未検討
- 「実害」と「既定」の境界判断が主観的になりやすく、分類基準を先に固める必要がある
