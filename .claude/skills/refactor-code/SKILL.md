# Refactor Code

コード構造の改善、コメントの整理、未使用コードの削除を通じてコード品質を向上させる。挙動を変えないこと、テストを通し続けることを担保する。

引数 (`$ARGUMENTS`) で対象パスが指定された場合、リファクタリング範囲をそのパスに限定する。

## 現在の状態

- Git status: !`git status --short 2>/dev/null || true`
- Project type: !`ls pyproject.toml package.json Cargo.toml go.mod 2>/dev/null || true`

## 進め方

作業ディレクトリがクリーンなことを確認し、ベースラインとして既存テストを実行してから着手する。以下を対象パスに行い、要所でテストを回して挙動不変を確認する。

- コメント整理: 更新履歴・コメントアウトされた古いコード・場当たり的な一時コメントを除去し、設計意図・アルゴリズム・重要な制約を説明するコメントは残す
- 構造改善: 長い関数の分割、重複の抽出、命名の明確化、複雑な条件の簡素化
- 未使用コード削除: 未使用の import・関数・デッドコードを静的解析と相互参照で特定する（reflection や文字列ベースの動的呼び出しに留意）
- テスト整合: リファクタで壊れた・不要になったテストを更新・削除し、最後に全テストが通ることを確認する

## 制約

- 大規模な構造変更、および未使用と判断したコードの削除は、着手前にユーザーへ確認する（使用状況に迷いがあれば消さない）
- コメントは設計判断・制約・落とし穴を説明するものを残し、明らかに陳腐化・一時的なものだけを除去する
- テストスイートがある場合、全テストが通るまでリファクタリング完了とみなさない
- 変更ごとに根拠とメリットを示し、削除候補は整理された一覧で提示する
- .md ファイルなどの出力および会話は日本語で行う
