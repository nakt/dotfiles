# Handover

現セッションの文脈を、新しいセッションが作業を再開するための 1 枚の資料に落とす。ゴールは「新セッションが追加質問なしに着手でき、同じ調査を繰り返さない」状態を作ることにある。

渡す先はフレッシュなセッションなので、こちらが何を調べ何を決めたかは一切伝わっていない。したがって書くべきは会話の経過ではなく、経過の結果として今わかっていることだけになる。

## Current state

- .workspace: !`ls .workspace/ 2>/dev/null || echo '(none)'`
- Today: !`date +%Y-%m-%d`
- Recent commits: !`git log --oneline -10 2>/dev/null || echo '(none)'`

## 1. 抽出

会話セッションを一次入力に、下記テンプレートの各節に入る材料を集める。会話に裏づけの無い項目は作らない(捏造しない)。

`$ARGUMENTS` にトピックのヒントがあれば抽出範囲をその話題に絞る。無ければ会話全体を対象にする。

## 2. 書き出し

保存先は `.workspace/NN_handover-<slug>/handover.md`。

- `NN` は Current state の `.workspace` 一覧にある数値プレフィックスの最大値 + 1。ディレクトリが無ければ `01`
- `<slug>` は内容を表す英小文字ハイフン区切り(例: `13_handover-oauth-token-refresh`)

### テンプレート

```markdown
# Handover: <一行タイトル>

## 依頼

新セッションにやってほしいこと。1-3 行。

## 背景

なぜこの話が出たか、元の会話でどこから派生したか。

## 調査済みの要旨

既に確認して結論が出ている事実。根拠(ファイルパス・コマンド・URL)を各項目に添える。
新セッションに同じ調査を繰り返させないことがこの節の目的。

## 決定事項

合意済みで覆さない前提。却下した案があればここに理由付きで書く。

## 未決の論点

新セッション側で判断が要る点。

## 参照

ファイルパス(行番号まで)、コミット、PR / issue 番号。
```

### 分量

節は必須ではない。次の 4 点を自分で確かめ、満たした時点で書き止める。

- 新セッションが何をすればいいか分かるか
- どこを見ればいいか分かるか
- 同じ調査を繰り返さずに済むか
- 却下した案を再提案しないか

各項目は、対応する材料が会話にあるときだけ問う。調査をしていない雑談発の引き継ぎに「同じ調査を繰り返さずに済むか」は該当しないし、案を比較していないなら「却下した案」も存在しない。該当しない項目は最初から満たされているものとして扱い、満たすために材料を作らない。会話に無いものを書けば、それは新セッションへ渡す捏造になる。

満たした項目と該当しない項目で 4 点が埋まったらそれ以上書かない。3 行で満たせるなら 3 行で終わる。節を必須にすると、些細な引き継ぎでも埋めるために内容を作ってしまい、逆に大きな引き継ぎでは必須節だけ埋めて足りたことにしてしまう。分量は節の数ではなく、渡す内容の大きさに追従させる。

- 中身が無い節は見出しごと落とす。空の節が残っていると、新セッションはそれを書き漏れと読んで探しに行く
- 会話ログを転記しない。結論と、その結論に至った根拠だけを書く
- 全体 100 行以内を目安にする。目安であって埋める目標ではない

### 事前確認

書き出す内容が 30 行を超える、または未決の論点がある場合だけ、節ごとの 1 行サマリを提示して採否を確認してから書く。それ以下なら確認せずそのまま書き出す。些細な引き継ぎでも使う想定なので、毎回の確認往復がこのスキルを使うコストになる。

## 3. 受け渡し

書き出したら `AskUserQuestion` で渡し方を 2 択で問う。

- パスを返すだけ: 絶対パスと 1 行サマリを提示して終了。ユーザーが自分で新セッションに渡す
- 別セッションに投げる: `ListAgents` で送信先を列挙してユーザーに選ばせ、`SendMessage` で送る

送信本文に入れるのは次の 3 点だけ。handover.md の絶対パス / まずそれを読んでから着手する指示 / 依頼の 1 行サマリ。本文に handover.md の内容を再掲しない。二重管理になり、handover.md を更新したときに食い違う。

`ListAgents` の候補が 0 件なら、その旨を伝えてパス提示にフォールバックする。
