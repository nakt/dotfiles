# AGENTS.md

このファイルは、Codex で作業する際の全プロジェクト共通ガイダンスを提供します。

## コミュニケーション

- 常に日本語で会話する
- 比喩表現を避け、状態を具体的に記述する（例: 「凍る」ではなく「応答が返らない」）

## コーディングガイド

コードを作成・変更する前に、対象ファイルの拡張子に応じたガイドを読み、その内容を実装と検証に適用する。

- `.py`: `/Users/nakt/.claude/skills/python-dev-guide/SKILL.md`
- `.ts`: `/Users/nakt/.claude/skills/typescript-dev-guide/SKILL.md`
- `.jsx`: `/Users/nakt/.claude/skills/react-dev-guide/SKILL.md`
- `.tsx`: TypeScript と React の両ガイドを読む。内容が矛盾する場合は React のガイドを優先する

同じタスクで複数種類の対象ファイルを変更する場合は、該当するガイドをすべて読む。

## Markdown ファイル作成時のスタイルガイド

### 基本方針

- 絵文字はユーザーが明示的に要求した場合を除き使用しない
- 強調（`**`）は本当に強調が必要な箇所だけに使用する
- 本文は文の終わり（`。`、`？`、`！`）で改行し、1文1行にする
- 箇条書き、テーブル、見出し、フロントマターは1項目1行のまま記述する
- 固定幅や見た目の都合で文の途中を改行しない

### 見出し構造

- 見出しレベルは1段ずつ下げ、飛ばさない

良い例

```markdown
# タイトル

## セクション

### サブセクション
```

悪い例

```markdown
# タイトル

### サブセクション
```

### Linter

- Markdown の変更後は PostToolUse hook が `markdownlint-cli2` を自動実行するため、同じ lint を重ねて実行しない
- hook から lint エラーが返った場合は、その内容に従って修正する

## `.workspace` ディレクトリ運用ルール

- 検証、一時実行、スクリプト実行結果などのファイルは、プロジェクトルートの `.workspace/` に保存する
- `/tmp` など、ほかの一時ディレクトリを使用しない
- `.workspace/` 直下に一時ファイルを置かず、作業単位でサブディレクトリを作成する
- 作業用ディレクトリは `NN_作業名/` 形式とし、数値には既存の最大値 + 1 を使用する。既存のディレクトリがなければ `01` から始める
- 恒常的に蓄積するディレクトリ（`audits/` など）には数値プレフィックスを付けない
- `.workspace/` はバージョン管理の対象外とし、`.gitignore` に追加する
